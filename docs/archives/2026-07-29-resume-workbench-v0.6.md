# 一次导入与双栏简历工作台 V0.6

## 本模块解决的问题

上一版虽然把主简历保存在浏览器本地，但岗位工作区仍保留大段粘贴框，使用户感觉每个岗位都要重新粘贴一次。修改建议与完整简历又分离，用户难以预判采纳后的整体效果。

岗位概览还展示固定的“匹配度”和“高于同类候选人百分比”。产品没有真实候选人样本、统一评价口径和验证集，这类数字无法被负责任地解释。

此外，工作台没有明确的 ChatGPT 退出和切换入口，用户容易把 ChatGPT 登录身份与产品后台 API Key 额度混为一谈。

## 已确认的产品方案

### 账号与 API 额度

- 工作台侧栏显示当前是否已登录 ChatGPT；
- 已登录时提供“切换”入口，先退出当前 ChatGPT 身份；
- 未登录时提供登录入口；
- ChatGPT 登录身份只用于识别用户和费用白名单；
- AI 调用仍使用产品后台统一配置的 API Key；
- 切换 ChatGPT 账号不会增加或切换 API 额度。

### 可信匹配

- 删除固定匹配分数和候选人百分位；
- 不对用户做不可验证的群体排名；
- 岗位概览只展示：
  - 已有简历原文证据的匹配项数量；
  - 可逐条确认的修改建议数量；
  - 当前简历未提供证据的 JD 要求数量；
- 分析尚未完成时明确显示“尚未开始”，不填入演示结论。

### 主简历一次导入

- 主简历统一在简历中心维护；
- 支持选择 `.docx` 文件；
- Word 文件在当前浏览器解析为文本，不上传原文件；
- 解析结果显示在编辑框内，由用户核对和修正；
- 主简历文本与文件名保存在当前浏览器；
- 替换或编辑主简历后，旧岗位分析自动失效，避免继续使用过期事实底稿；
- 岗位专属历史版本继续保留。

### 双栏简历定制

1. 用户进入真实岗位的“简历定制”；
2. 系统自动读取简历中心的主简历；
3. 用户点击“开始 AI 匹配分析”；
4. 左侧展示逐条修改建议、修改原因和 JD 原文依据；
5. 用户采纳建议后，右侧完整岗位简历立即替换对应表述；
6. 用户取消采纳时，系统在能够安全定位的情况下恢复原表述；
7. 用户可直接在右侧继续编辑完整简历；
8. 用户选择“完成修改并保存版本”，建立独立岗位版本；
9. 用户选择“导出 PDF”，打开浏览器打印窗口并保存为 PDF。

## 当前实现边界

- 支持 `.docx`，暂不支持旧版 `.doc`；用户需先另存为 `.docx`；
- Word 首版只提取文字，不保留原 Word 的字体、表格、分栏、头像和精确排版；
- PDF 首版使用 A4 打印样式输出，不承诺自动还原原 Word 视觉；
- 右侧编辑器是岗位副本，不覆盖主简历；
- 复杂简历模板、分页控制、排版主题和直接生成可下载 PDF 文件后续迭代。

## 隐私与安全边界

- Word 原文件不上传；
- 主简历、岗位副本和版本正文保存在当前浏览器；
- 只有用户主动点击分析时，主简历文本与当前 JD 才临时发送给模型；
- OpenAI 请求继续使用 `store: false`；
- 服务端不记录或保存简历正文。

## 验证

- 构建通过；
- 岗位解析、证据校验、API 错误和简历流程共 14 项测试通过；
- 回归测试确认页面不再出现“高于同类候选人”和固定百分位；
- 回归测试覆盖 Word 解析入口、账号切换入口、双栏完整编辑框与 PDF 导出入口。

## 下一步

使用一份真实 `.docx` 简历完成一次端到端操作，观察：

- Word 文本解析是否丢失关键段落；
- AI 建议是否能准确定位原文；
- 采纳与取消采纳是否符合预期；
- 右侧直接编辑是否足够顺手；
- 浏览器打印出的 A4 PDF 是否满足首轮投递需要。
