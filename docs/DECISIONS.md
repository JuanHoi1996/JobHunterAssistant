# 已确认的产品决策

更新日期：2026-07-28

## 产品与用户

- 产品暂定名为“向前 · 求职工作台”。
- MVP 面向校招及毕业 0—3 年求职者。
- 首批重点岗位类别为运营、产品、法务。
- 首版中文优先，简历输出先支持 PDF，Word 后续补充。

## 数据与权限

- 通用岗位与投递数据保存在 Web 产品中。
- 简历、身份证件等敏感个人资料优先保存在本地插件中。
- 不要求用户向 Agent 提供招聘网站密码、验证码或 Cookie。
- 用户自行登录招聘网站，插件只在用户主动操作时读取当前页面或辅助填表。
- MVP 不自动完成最终投递提交。

## 岗位来源

- MVP 不建设全网岗位聚合和持续同步能力。
- 岗位由用户主动收录，支持链接、JD 文本、截图和插件一键保存。
- Agent 提取结构化岗位字段，用户确认和修正后才创建记录。
- 记录“在哪里看到岗位”；投递方式在用户标记已投递时再可选记录。
- 当前可用版本先只开放“粘贴 JD 文本”，优先打磨字段提取准确率和岗位记录闭环。
- 岗位链接、截图上传和插件保存保留为后续入口；在真实能力接入前显示“暂未开放”，不得进入空白确认页。

## 岗位状态

- 新收录岗位默认状态为“待投递”。
- 岗位状态与简历、Cover Letter 等材料准备进度分开显示。
- MVP 状态为：待投递、已投递、面试中、Offer、已结束。
- 用户手动标记“已投递”，系统记录投递时间并停止待投递提醒。
- 待投递岗位收录超过 24 小时后显示简洁的站内提醒。

## 文档与版本控制

- 每完成一个相对独立模块，建立一份 Obsidian 兼容 Markdown 归档。
- 每次归档后建立对应 Git 检查点。
- 项目文档和 Git 历史是跨 AI 交接的事实来源。
