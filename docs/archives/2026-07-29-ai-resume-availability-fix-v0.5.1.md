# AI 简历分析可用性修复 V0.5.1

## 本次解决的问题

用户完成 ChatGPT 登录并粘贴真实简历后，点击“开始 AI 匹配分析”只看到“AI 简历分析暂时不可用”，无法判断下一步该做什么。

生产日志显示：

- 登录前请求按预期返回未授权；
- 登录并通过费用白名单后，请求进入简历分析接口；
- OpenAI 上游请求失败，接口约一秒后返回 502；
- 旧实现丢弃了上游状态与错误类型，因此无法区分额度、密钥、模型、请求格式或网络问题。

## 已完成

- 继续使用 Responses API 和结构化输出，不改变简历分析的数据契约；
- 将模型推理强度显式设置为 `low`，控制 MVP 的等待时间与成本；
- 将 OpenAI 上游失败分为：
  - API 额度不足或请求过多；
  - 密钥无效或没有模型权限；
  - 模型配置不可用；
  - 请求配置不兼容；
  - 请求超时；
  - 网络连接失败；
  - 模型结果未通过真实性校验；
- 页面沿用原有错误区域展示可操作的中文提示；
- 生产日志只写入模型名、上游状态码、错误代码、错误类型和请求编号；
- 不记录 JD、简历正文或上游错误消息；
- 为错误分类补充自动化测试。

## 隐私与安全边界

- 用户真实简历未进入测试样例、项目文档或版本库；
- OpenAI 请求继续使用 `store: false`；
- 简历正文仍只在用户点击分析时临时发送；
- 服务端不保存简历正文；
- 日志不得包含请求正文或模型返回正文。

## 验证

- 生产故障路径已从站点 Worker 日志确认；
- 完整构建通过；
- 14 项岗位、简历证据与错误分类测试通过；
- 相关文件通过 ESLint。

## 下一步

发布后由已获授权用户重新点击一次“开始 AI 匹配分析”。如果上游仍失败，页面将给出可执行原因，同时生产日志会提供不含个人信息的诊断字段，据此完成最后的运行环境修正。
