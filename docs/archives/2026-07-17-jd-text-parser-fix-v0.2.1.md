# JD 文本识别修复 V0.2.1

## 问题

用户粘贴北京通商（成都）律师事务所的长期实习生 JD 后，确认页错误显示为“腾讯 / 产品运营实习生 / 深圳”。

这不是模型理解偏差，而是 V0.2 可点击原型的确认表单仍使用固定演示值。无论粘贴什么文本，页面都会返回同一组产品运营数据，属于会误导用户的严重数据真实性问题。

## 本次修复

- 删除新增岗位表单中的腾讯、深圳、产品运营等固定默认值；
- JD 文本改为受控输入，解析时读取用户实际粘贴的内容；
- 从带标签的中文 JD 中提取招聘单位、岗位名称、工作地点和业务方向；
- 根据原文判断工作性质与岗位类别；
- 提取毕业年份、实习时长、法律职业资格和投递邮箱等明确事实；
- 摘要只组合原文能够确认的信息，不补写原文没有的内容；
- 未识别到的字段保持空白并提示用户补充；
- 公司名称和岗位名称作为创建记录的最低必填项；
- 新建岗位后保留 JD 原文，并在详情页显示真实解析结果；
- 新建岗位未完成简历匹配前，不再展示产品运营示例分析。

## 回归样例

本次使用用户提供的真实 JD 建立自动测试，预期结构化结果为：

| 字段 | 结果 |
| --- | --- |
| 招聘单位 | 北京通商（成都）律师事务所 |
| 岗位名称 | 长期实习生 |
| 工作地点 | 成都 |
| 工作性质 | 实习 |
| 岗位类别 | 法务 |
| 业务方向 | 境内外资本市场 |
| 毕业年份 | 2027 |
| 连续实习时长 | 3 个月以上 |
| 投递邮箱 | luopeishan@tongshang.com |

测试同时检查解析结果中不得出现“腾讯”“产品运营”“深圳”等演示数据。

## 其他收录方式的边界

为了避免继续产生虚假识别结果，当前公开原型对尚未接入的能力做了明确降级：

- 岗位链接：尚未接入真实网页读取服务，进入确认页后由用户手动补充；
- 岗位截图：尚未接入 OCR 或视觉模型，选择图片后由用户手动补充；
- 插件保存：尚未与 ResumeFiller 建立通信，由用户手动补充；
- 以上方式不再返回任何预设公司或岗位数据。

## 技术边界

当前实现是浏览器端的规则解析器，适合“招聘单位：”“招聘职位：”“工作地点：”等常见结构化中文文本。它已经能正确处理本次样例，但不能替代后续的通用 AI 结构化提取服务。

正式 MVP 下一阶段应将规则解析作为快速兜底，并增加模型结构化输出、字段证据、置信度和失败重试机制。

V0.2.2 已增加自由格式页头解析和字段原文依据，详见 `2026-07-17-jd-reliable-extraction-v0.2.2.md`。
