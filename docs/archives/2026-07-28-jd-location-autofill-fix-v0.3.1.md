# JD 地点自动填入修复 V0.3.1

## 本次解决的问题

当 JD 使用 `📍 工作地点：上海新江湾` 这类带定位图标的明确标签时，确认页会显示正确的原文依据，但“工作地点”输入框为空。

## 根因

证据检索允许“工作地点”出现在一行中的任意位置，因此能找到完整依据；结构化取值规则则要求“工作地点”必须直接出现在行首。定位图标位于标签前时，取值规则无法匹配，造成“有证据、无字段值”的不一致。

## 已完成

- 明确地点标签前允许出现 `📍` 或 `📌`；
- 继续保留明确标签后的详细地点，不把“上海新江湾”截断为“上海”；
- 地点值正常进入确认页输入框和 JD 摘要；
- 新增真实失败形态的自动化回归测试；
- 使用虚构测试邮箱，未把用户截图中的联系方式写入代码或归档。

## 验证结果

- `📍 工作地点：上海新江湾` 提取为 `上海新江湾`；
- 原文依据保持为 `📍 工作地点：上海新江湾`；
- 摘要包含“工作地点为上海新江湾”；
- 岗位解析与模型合并测试共 7 项全部通过；
- 生产构建通过。

## 产品边界

- 本次仅修复明确地点标签前存在定位图标的情况；
- 未改变 LLM 调用权限、岗位状态、来源渠道或 24 小时提醒等已确认决策；
- 无明确原文依据时仍不自动编造地点。

## 下一步

继续收集真实失败样例，并按“原文—期望字段—实际字段”加入回归测试集，逐步覆盖其他常见排版符号和地点表达。
