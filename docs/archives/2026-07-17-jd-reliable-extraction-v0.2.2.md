# JD 可靠识别机制 V0.2.2

## 问题背景

V0.2.1 能识别“招聘单位：”“招聘职位：”“工作地点：”等带标签文本，但无法正确处理以下自由格式页头：

```text
字节跳动Tiktok Shop
推荐产品实习生（诊断Agent方向）
📍Base：北京 八月份可到岗
```

结果是工作性质和岗位类别能够根据全文推断，但公司、岗位和地点三个关键字段为空。

## 产品结论

对于任意用户粘贴的自由格式 JD，任何单一正则或大模型都无法合理承诺“每一次、每个字段绝对正确”。产品真正需要保证的是：

1. 能确认的字段尽可能自动提取；
2. 每个自动字段能够指向原文依据；
3. 无法找到依据或相互矛盾时，不静默写入；
4. 公司、岗位、地点等关键字段由用户在创建记录前最终确认；
5. 已发现的真实失败样例必须成为永久回归测试。

因此，正式目标定义为“高提取覆盖率 + 关键字段静默错误为零”，而不是对开放文本作无法验证的 100% 准确承诺。

## 本版已经实现

### 自由格式页头

- 当前几行没有字段标签时，可根据页头结构识别公司行和岗位行；
- 支持“实习生、管培生、产品经理、工程师、分析师、专员、顾问、律师”等常见岗位标题信号；
- 支持 `Base：北京`、`📍Base：北京 八月份可到岗` 等地点格式；
- 地点值会排除“可到岗、可入职”等时间说明。

### 字段判断

- “推荐产品实习生”识别为工作性质“实习”、岗位类别“产品”；
- 岗位类别优先根据岗位标题判断，避免正文中“增长、运营”等业务词干扰分类；
- 对常见企业品牌进行规范化，例如“字节跳动Tiktok Shop”归一为“字节跳动”；
- 同时提取主投递邮箱和抄送邮箱。

### 原文证据

确认页会在公司、岗位、地点、工作性质和岗位类别下方展示原文依据，例如：

```text
公司名称：字节跳动
依据：“字节跳动Tiktok Shop”

工作地点：北京
依据：“📍Base：北京 八月份可到岗”
```

“有原文依据”只表示系统能指出来源，并不替代用户确认。

## 正式 MVP 的可靠识别架构

当前浏览器端规则解析器是第一层，不是最终方案。正式版本采用以下多层机制：

1. **文本预处理**：统一换行、标点、空格、OCR 噪声和网页残留；
2. **高精度规则提取**：优先处理明确标签、邮箱、地点和页头结构；
3. **模型结构化提取**：模型只返回固定 JSON 字段，并为每个字段同时返回原文引用和置信度；
4. **证据验证**：后端检查引用必须真实存在于原始 JD；找不到原文的字段不得作为“已识别”写入；
5. **一致性校验**：检查“实习生—实习”“法务—法律关键词”、邮箱格式、地点格式等跨字段关系；
6. **置信度分流**：高置信度自动预填，中置信度标记需核对，低置信度留空；
7. **用户确认**：用户修改或确认后才创建正式岗位记录；
8. **回归样例库**：匿名化保存失败结构，将每次线上错误转为自动测试。

## 建议验收指标

- 已收录回归样例通过率：100%；
- 公司、岗位、地点的“无证据自动填入”数量：0；
- 关键字段静默错误率：0，发现不确定时必须进入需核对状态；
- 自由格式 JD 关键字段自动预填覆盖率：内测阶段持续统计，不提前虚构目标值；
- 用户修正率按字段统计，用于发现最薄弱的解析环节。
