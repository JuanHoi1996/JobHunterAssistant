# 简历分析缓存迁移 V0.9.1

## 问题

简历分析引擎升级到 V0.9 后，分析结果新增了 `jdPriorities`、`highlights`、
`questions`、多条 `sourceEvidence` 等字段。浏览器中可能仍保存着旧接口或开发热更新
期间产生的部分分析结果。

用户点击简历建议时，前端直接读取缺失字段的 `.length`，触发：

`Cannot read properties of undefined (reading 'length')`

整个简历定制页面因此被运行时错误遮挡。

## 修复方案

新增统一的 `normalizeStoredResumeAnalysis`：

- 在从 LocalStorage 恢复分析记录时执行迁移；
- 在把当前岗位分析传给概览页和简历页前再次执行防御性归一化；
- 在用户采纳或编辑建议后写回分析状态前保持统一结构；
- 缺失的列表字段补为空数组；
- 旧版单条字符串证据转换为字符串数组；
- 缺失的建议优先级和改写类型补为安全默认值；
- 缺失 `sourceEvidence` 时只回退到该建议已有的 `original`；
- 清除越界或非整数的已采纳索引；
- 无效分析记录不会进入界面。

安全默认值只用于保持界面可读，不会被视为新的 JD 或简历事实，也不会触发自动采纳。

## 验证

- 增加一个缺少全部 V0.9 新字段的旧缓存回归样例；
- 验证旧版字符串证据可以迁移为数组；
- 验证越界采纳索引会被删除；
- 构建通过；
- 24 项自动测试全部通过；
- 本地浏览器进入真实岗位并点击“简历定制”后页面正常显示；
- 浏览器控制台未出现新的错误。

## 后续规则

以后只要分析结果的数据结构发生变化，都必须同时提供：

1. 服务端结果校验；
2. 浏览器缓存迁移；
3. 渲染层安全默认值；
4. 至少一个旧结构回归测试。

不能只修改 TypeScript 类型，因为类型声明不会自动改变用户浏览器里已经保存的数据。
