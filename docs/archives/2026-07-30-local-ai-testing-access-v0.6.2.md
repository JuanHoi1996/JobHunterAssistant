# 本地 AI 测试访问修复 V0.6.2

## 问题

DeepSeek Key 已在本地 `.env.local` 正确配置，并已通过无个人信息的 API 请求验证。浏览器打开本地工作台后，岗位收录仍显示“当前账号未启用 AI 语义识别”。

原因是原有 AI 白名单只读取 Sites 注入的 ChatGPT 身份请求头。本地 `localhost` 开发服务没有该身份头，因此错误进入规则解析降级。

## 修复

- 在岗位提取与简历分析 API 中增加严格的本地开发例外。
- 仅当 `NODE_ENV` 不为 production，且请求主机为 `localhost`、`127.0.0.1` 或 `::1` 时，允许使用已配置的模型。
- 其他请求仍必须通过既有的 ChatGPT 身份白名单验证。

## 安全边界

- 例外不适用于任何生产环境请求。
- 不修改公开站点的登录或费用白名单策略。
- API Key 继续只存在于本地 `.env.local` 或生产环境私密变量，客户端不可读取。
- 模型调用仍只发生在用户主动点击岗位提取或简历分析时。

## 验证

- 构建通过。
- 16 项回归测试通过。
- 回归测试明确检查 localhost 例外与生产白名单代码同时存在。

## 用户操作

更新代码后需停止并重新执行本地 `pnpm dev`，再刷新浏览器页面，新的本地 API 路由才会生效。
