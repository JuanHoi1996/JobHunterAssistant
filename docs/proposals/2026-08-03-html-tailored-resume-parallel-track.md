# 岗位专属简历平行轨：HTML 全局成稿？

> 本文是**提案**，不是已确认决策。确认前不得替换现有「逐条采纳 + 保留原 Word 模板」路径。
>
> **本 PR 仅文档。** 任何实现须另开独立实验/功能 PR，且默认不取代现有简历定制页。

## 结论（先读这段）

1. 现有 V0.9 路径擅长**可信的局部改写**，但在严校验下，用户观感容易变成「看着跟没改一样」。
2. 真正的 tailored resume 需要**全局叙事**（排序、取舍、各段如何服务 JD），而不仅是遣词造句；LLM 仍负责策略与措辞，模板负责版式。
3. 建议增加一条**平行实验轨**：LLM 输出结构化履历 JSON → 填入 HTML 模板 → 浏览器预览 / 打印为 PDF。**不删除、不默认替换**现有 docx 逐条流。
4. 首批使用者可假定为产品负责人本人（及少数共创者），因此可用「一人一模板 / 手调 schema」降低工程复杂度；这不是对外通用排版引擎的承诺。

一句话给 Agent：

> Add an optional parallel “global tailored resume” experiment (structured JSON + HTML template → PDF preview). Keep the existing evidence-bound suggestion pipeline. Do not merge implementation into this docs PR. Confirm product boundaries before coding.

## 要解决的问题

- 用户反馈：AI 改简历「看起来像没改」。
- 根因不只是提示词：交付形态是「3–6 条可替换原文片段」+ 禁止升级词/新数字，天然偏向微调。
- 目标：验证「全局成稿」是否显著改善「为该 JD 定制过」的观感，同时不破坏现有真实性原则。

## 与已确认决策的关系

现行 `docs/DECISIONS.md` 已确认：

- 双栏逐条采纳；
- 岗位专属版优先保留原 `.docx` 模板导出；
- 只允许安全回写段落内文字；
- 浏览器打印仅为「纯文本 PDF」备用。

本提案**不推翻**上述决策，而是请求确认：

> 是否允许在保留轨 A（docx + 逐条）的同时，增加可选轨 B（HTML 全局稿）作为实验入口？

若否决轨 B，应明确「观感太平」只能在轨 A 内通过提示词/校验/蓝图增强解决。

## 双轨定义

| 轨 | 形态 | 用户控制 | 主要价值 |
|----|------|----------|----------|
| A（现有） | 局部建议 + 原 Word 回写 | 逐条采纳 | 信任、投递格式兼容、可追溯 |
| B（提案） | 结构化 JSON 填 HTML → 预览/PDF | 先出整稿，再人工改 | 全局排序/取舍/叙事，观感「改过」 |

LLM 用途（轨 B）：

- 从 JD + 简历生成**策略**（保留/弱化/前置哪些经历）；
- 生成填入模板的**措辞**（仍须事实可追溯）；
- **不是**用 LLM 直接「操作 docx」。

非 LLM：HTML 模板渲染、分页预览、打印/另存 PDF。

## 一人用场景下的简化（明确非对外承诺）

当前产品主要为负责人自用验证。因此轨 B 原型可以：

- 只维护 **1 套** HTML 模板（或产品/运营各一套硬编码）；
- schema 按负责人真实简历字段定制，多出来的经历用「可选块」显示/隐藏，而不是通用自适应引擎；
- 不要求覆盖任意用户的任意板块组合。

若未来有外人使用，再单独评估「动态区块 / 多模板市场」——不在本提案范围。

## 建议的最小原型（确认后再开代码 PR）

1. 隐藏或明确标注的实验入口（例如岗位工作区「全局定制预览（实验）」）。
2. 一次 LLM 调用（或沿用蓝图后再一次）输出约定 JSON。
3. 固定 HTML 模板渲染；浏览器预览；打印对话框另存 PDF 即可（不承诺像素级排版）。
4. 真实性：至少复用「禁升级词 / 禁新数字」精神；理想情况对每条 bullet 保留 sourceEvidence（可先做弱约束 + 人工审）。
5. **验收**：同一 JD 下，负责人主观判断轨 B 是否明显比轨 A「更像定制过」；不通过则停，不扩大范围。

## 明确非目标

- 不替换轨 A，不改默认导出为 HTML。
- 不实现通用「任意简历 → 任意模板」映射引擎。
- 不在本阶段上重型 PDF 排版服务。
- 不与 Windows 脚本、路由实现、提示词微调等无关 PR 混提。
- 贡献者不承诺完整手工测试矩阵；由产品负责人在自用场景验收。

## 风险

| 风险 | 缓解 |
|------|------|
| 与「Word 模板优先」叙事冲突 | 文案标明实验轨；默认仍走轨 A |
| HTML 稿更易写虚 | 保留证据字段；负责人审阅；必要时共用校验词表 |
| schema 与真实简历不对齐 | 一人一模板；缺块隐藏、多块截断并提示 |
| 双轨维护成本 | 实验开关；未通过验收则删除入口 |

## 请产品负责人确认

1. **是否允许**平行实验轨 B（HTML 全局成稿）？
2. 轨 B 若可用，最终投递形态接受 **仅 PDF**、还是必须仍能导出 Word？
3. 实验入口放在现有「简历定制」旁，还是完全独立页？
4. 确认后：由贡献者开 `experiment/…` 或 `feat/…` **Draft PR** 做最小竖切；本提案 PR 仍只含文档。
