# 岗位收录与投递状态 V0.1

## 本模块解决的问题

求职者经常把岗位 JD 发给自己或临时收藏，计划稍后投递，但最终因为忘记、
材料未准备好或信息分散而没有完成投递。本模块将“收藏岗位”转化为可持续推进的
个人求职任务。

## 已确认决策

### 四种收录方式

1. 粘贴岗位链接；
2. 粘贴 JD 文本；
3. 上传岗位截图；
4. 浏览器插件一键保存当前岗位。

链接无法读取、需要登录或遇到验证码时，不要求用户向 Agent 提供账号密码，
改用插件读取当前已登录页面、截图或 JD 文本。

### 提取与确认

- Agent 提取公司、岗位名称、地点、岗位类型、JD、截止日期和原始链接等字段；
- 用户确认或修正后才创建岗位记录；
- 低置信度和未识别字段需要明确标示；
- 截图支持裁剪和打码，默认不长期保存未经处理的原图。

### 来源与投递方式

- 创建岗位时只询问“你在哪里看到这个岗位？”；
- 可选来源包括 BOSS直聘、企业官网、微信公众号、实习群、学校就业网、
  小红书、朋友推荐、内推和其他；
- 投递方式不在创建时强制填写；
- 用户标记已投递时，可选记录企业官网、BOSS、邮件、内推或其他方式；
- 数据层保留发现来源和投递方式两个字段，界面分阶段采集，避免混淆。

### 状态与准备进度

- 新收录岗位默认状态为“待投递”；
- 岗位状态为：待投递、已投递、面试中、Offer、已结束；
- 简历优化、Cover Letter 和邮件正文使用独立的材料准备进度；
- 材料完成不自动等于已投递；
- 用户完成外部投递后手动点击“标记为已投递”。

### 24 小时提醒

触发条件：岗位收录超过 24 小时，并且仍处于待投递状态。

推荐文案：

> 这个岗位已收录 24 小时，建议今天完成投递。

主要操作：

- 继续准备；
- 标记已投递。

用户将岗位标记为已投递、已结束或放弃后停止提醒。MVP 先使用站内提醒，
暂不增加短信、邮件或高频系统通知。

## 核心用户流程

```text
发现岗位
→ 选择链接、JD、截图或插件保存
→ Agent 提取岗位字段
→ 用户确认与选择发现来源
→ 创建待投递记录
→ 分析 JD 和准备求职材料
→ 超过 24 小时仍未投递时提醒
→ 用户在外部完成投递
→ 手动标记已投递并可选记录投递方式
```

## 数据字段 V0.1

- `capture_method`：链接、文本、截图、插件或手动；
- `discovery_source`：用户在哪里发现岗位；
- `application_method`：用户最终如何投递，可为空；
- `status`：当前岗位状态；
- `saved_at`：岗位收录时间；
- `submitted_at`：实际投递时间，可为空；
- `last_activity_at`：最近一次准备或修改时间；
- `reminder_dismissed_until`：稍后提醒截止时间，可为空。

## 权限与隐私边界

- 不收集招聘网站密码、验证码或 Cookie；
- 用户自己完成登录和身份验证；
- 插件只在用户主动点击后读取当前页面或辅助填写；
- MVP 不自动点击最终提交；
- 原始截图上传前允许裁剪和打码；
- 未清理的聊天日志和工具输出不作为产品数据保存。

## 已完成

- 产品逻辑和状态规则已确认；
- 已明确岗位来源、投递方式和导入方式的区别；
- 已确定 24 小时提醒条件和推荐文案；
- 已确定登录受限页面由插件读取，不由远程 Agent 模拟登录。
